# Haunted House v0.1 — controlled Ghost Busters regression corpus

**Synthetic, source-only benchmark pilot.** Six pairs of a suspicious source
and a *matched safe/counterexample source* are stored under `fixtures/h-XX`.
`cases.json` records the author-prepared oracle and exact Git Blob identities.
None of these files or their network/financial functions are executed.

| ID | Mechanism | Automated by the public skill scanner? |
| --- | --- | --- |
| H-01 | swallowed JSON error | no; agent/human scenario |
| H-02 | zero-row mutation with misleading success | no; agent/human scenario |
| H-03 | webhook check-then-insert | no; agent/human scenario |
| H-04 | async `forEach` completion lie | no; agent/human scenario |
| H-05 | stale UI reply | no; agent/human scenario |
| H-06 | row-cap truncation | yes; bounded existing `scan-unbounded-reads` signature |

## Run deterministic META-GHOST smoke

~~~sh
npm install --ignore-scripts --no-audit --no-fund
node evals/haunted-house/verify.cjs --json
~~~

The verifier checks **all 12 fixture Git Blob hashes** and whether the exact
expected files are present; it runs only the existing trusted static row-cap
scanner against H-06. Fails closed if parser unavailable, the scanner returns
invalid JSON, a file is missing or the expected positive/negative signatures
change. A successful 1-positive/1-negative smoke check is **not** general
precision or recall for six classes, nor independent real-world validation.

## Separate agent / human evaluation

Supply only fixture source files to the evaluated agent; **withhold the answer
file `cases.json`** and any report generated by a previous run. Because
answer labels are published in this same repository, a truly blind external
study would need separately held-out, independently labelled cases and control
over source access.

Predictions are a JSON object:

~~~json
{
  "schemaVersion": "haunted-house-predictions-0.1",
  "predictions": [
    {
      "caseId": "H-01", "variant": "a", "decision": "BUG",
      "file": "fixtures/h-01/a.ts", "line": 18,
      "trigger": "upstream returns invalid JSON",
      "falsifier": "the documented contract explicitly treats failure as an empty business result"
    },
    {"caseId": "H-01", "variant": "b", "decision": "SAFE"}
  ]
}
~~~

Decision: `BUG | SAFE | UNKNOWN`. A BUG requires file:line, trigger and
falsifier. Missing or UNKNOWN cases are reported as **UNKNOWN**, not silently
classified as safe. Score using:

~~~sh
node evals/haunted-house/score.cjs --input /outside/repo/predictions.json --json
~~~

The scorer measures TP/FP/FN/TN on author-labelled examples *among answered
variants*, and the separate UNKNOWN count. It does **not** verify the agent's
interpretation, runtime behavior or provenance; independent manual adjudication
and held-out cases are necessary before comparison of detector quality.

## Research protocol

Pin agent/model versions, prompts, runtime, time and token budgets; randomize
A/B assignments; keep the original predictions before revealing labels.
Compare baseline Ghost Busters instructions vs the updated lenses at matched
costs. Stop/rollback if false-positive count rises, evidence is spuriously
promoted or known-safe fixtures are claimed as confirmed bugs.
